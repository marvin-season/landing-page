# 世界群聊

入口：`/agent/worlds`。沿用 `/agent` 登录保护，新建页面，不改变现有单聊入口。

## 使用

1. 启动本地 Agent 代理，再运行 `nr dev`，打开 `http://localhost:3001/agent/worlds`。
2. 点击“创建世界”或选择示例，设置背景、规则、故事推进要求与 2～7 位 NPC。用户是故事外的系统操作者，不扮演场内人物。
3. 配置面板可以获取代理模型或测试连接。保存预设不生成内容；创建并进入新世界后自动开始。
4. 没有用户输入时，主持人和 NPC 依据当前设定、推进要求和已发生的事件持续逐条行动。NPC 之间的问题由 NPC 回答，不因等待玩家选择而停下来。
5. 输入系统干预，例如“让暴雨停下来，大家开始调查备用电路”，会中止当前生成，并按新要求继续。干预单独标记，不作为 NPC 台词；`@` 可指定 NPC 优先行动，之后恢复自动选人。
6. 随时暂停或使用“仅下一条”。手动暂停后，普通提交只保存干预；“干预并继续”恢复运行。异常、单步、重试和离开页面后不自动续跑，手动继续即可。
7. 暂停后可修改设定、推进要求、公共事实、NPC 配置或模型。已开始的世界不增减角色，可复制为新世界。
8. 世界列表可删除存档；“设定”面板提供导出、完整备份、复制和结束故事。完整备份包含角色私有信息，不包含 API 密钥或模型推理文本。

旧预设、存档和备份会兼容转换：原玩家角色成为 NPC，旧玩家台词按该 NPC 的历史言行保留，不升级为系统干预。旧的等待玩家规则不再控制调度；已暂停的存档和导入的备份仍需手动继续。最多允许 7 位 NPC，以容纳旧版 6 位 NPC 加 1 位玩家。

世界预设与角色预设可以独立保存。选择已有预设后可修改并更新；创建房间时保存配置快照，之后修改预设不会改变已有房间。导入完整备份时创建新房间、新消息 ID，不覆盖现有存档；摘要从公共历史重新整理，运行不会自动恢复。

## 服务端配置

配置均只在服务端读取，示例见根目录 `.env.example`：

- `GROUP_CHAT_BASE_URL`：默认 `http://127.0.0.1:3425/v1`。
- `GROUP_CHAT_API_KEY`：默认使用用户本机代理示例中的开发密钥 `magpie`；接入其他代理时设置对应密钥。
- `GROUP_CHAT_DIRECTOR_MODEL`：可选。未设置时调度器使用候选角色的模型。
- `GROUP_CHAT_DATABASE_URL`：默认 `file:./db/group-chat.db`，与现有 Mastra 单聊数据库分开。
- `GROUP_CHAT_DATABASE_TOKEN`：可选，远程 libSQL 存储使用。

角色模型默认 `cursor/auto`，可在配置表单中修改。浏览器通过同源 API 访问，服务端通过 Mastra Agent 和 OpenAI-compatible provider 调用代理；无需浏览器跨域访问本地代理。

运行基线是单个常驻 Node 进程。远程部署时 `127.0.0.1` 指向服务器自身；必须配置服务器可达的代理及持久化数据库。关闭页面/断开连接会取消运行，进程崩溃的运行在租约过期后标为中断，不自动续跑。

## 实现边界

- 单房间一位系统操作者、2～7 位 NPC；当前没有多真人协作、私聊、历史分支、媒体生成或工具执行。
- `mastra-server/agents/world-agents.ts` 注册角色、调度、旁白和摘要四类 Agent。每次调用独立传入模型和上下文，不共享自动 Memory，也不继承普通单聊的工具；复用 Mastra 实例的日志与追踪。
- `src/lib/group-chat/provider.ts` 将 Mastra 流转换为现有 `Complete` 契约，保留超时、中止、完整性检查、文本上限和错误码。模型列表仍使用 OpenAI SDK 的 `/models`。
- 模型 ID（例如 `cursor/auto`）原样传给代理。专用 provider 强制发送 `tool_choice: none`，无工具注册，非文本工具流也会被拒绝。
- 世界存档、版本、幂等、运行租约和事件协议仍由现有世界模块管理，不以 Mastra Memory 替代，也不使用自动规划的 Network。
- 用户干预独立存为 `intervention` 消息；最新干预即使已进入摘要仍单独提供。摘要保留持续要求，并区分已实现的事件与待实现的安排；模型负责将叙事要求落实到内容，不提供确定性的故事结果保证。
- 房主能查看全部角色设定。“秘密”指角色之间的模型输入隔离，不是对房主保密。NPC 仅收到自己的私有目标与资料，主持人和摘要只收到公开角色资料。
- 明确指向 NPC 的问题或指令直接交给对应角色；其他情况由调度 Agent 选择。点名按顺序优先处理；选人超时（8 秒）、无效输出或旧格式 `wait` 使用确定性兜底，继续安排 NPC，不自动暂停等待操作者。
- NPC 用第一人称短句与其他 NPC 自然交谈，主持人负责短旁白、环境变化与行动反馈。角色、旁白和干预进入公开历史，配置变更等 `system` 通知不进入剧情。
- 页面通过同一可取消订阅接续有界运行，`maxTurns` 保留为每批大小，不再作为故事的自动停止条件。只有上一批正常完成时才接续；单步、重试、手动暂停、异常和离开页面均不自动续跑。续跑绑定上一运行 ID，暂停还会封锁尚未到达服务端的请求，避免迟到请求重新启动故事。
- 每轮最多 180 秒、25 次调用，单个请求最多 60 秒、30 秒无事件超时；角色正文上限 2,000 字符。应用取消不等于代理上游一定停止计费。
- 使用公共历史滚动摘要，并保留原始消息；未完成片段不进入后续上下文。输入采用保守的字符预算，不声称精确匹配所有模型的 token 窗口。配置过长会暂停并提示缩减。
- 成功消息在事务提交后才标为完成。生成中的片段定期保存；服务骤停时最后一个检查点之后的未提交片段可能丢失。数据库失败会终止调度并保留可恢复片段；目前没有独立的“仅重试保存”队列。
- 角色输出为模型生成，世界规则属于叙事约束；暂停、预算、访问权限和上下文资料过滤由程序控制。
- 首次读取最多返回 100 条消息，页面可继续加载更早历史。首版本机存档采用房间 JSON 文档加事务、请求幂等表和运行租约；不是面向大规模多人系统的分布式事件存储。
- 管理与流式接口统一使用 Route Handlers，避免给仅此页面使用的能力同时维护两套 HTTP/tRPC 契约；原有单聊 tRPC 不变。

## 代码与验证

- 页面与表单：`src/app/agent/worlds/`。
- 内置世界模板：`public/worlds/*.json`，文件名即模板 id，由 `world-templates.ts` 扫描读取。`public/worlds/local/*.json` 为本机模板，同样扫描，但不提交。
- API：`src/app/api/group-chat/[[...path]]/route.ts`，包含鉴权、来源和房间所有权校验。
- 领域、上下文、存储和调度：`src/lib/group-chat/`。
- 传输：复用共享 `useChatStreamCore`，使用 AI SDK 的 SSE 解析器读取房间事件；Mastra Agent 与 OpenAI-compatible provider 负责生成协议。
- `nr test:group-chat`：存档、权限、上下文隔离、自动调度与连续接续、点名优先、幂等、回复之间暂停、取消竞态、摘要和协议边界测试。
- `nr check`：代码规范检查。
- `node_modules/.bin/tsc --noEmit --incremental false`：类型检查。

UI 由用户手工验收；单元测试验证控制流、存档与协议边界，不保证模型生成质量。

产品评估与后续方向见 [需求文档](./requirements/agent-group-chat-prd.md)。
