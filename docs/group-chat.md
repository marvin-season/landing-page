# 世界群聊

入口：`/agent/worlds`。沿用 `/agent` 登录保护，新建页面，不改变现有单聊入口。

## 使用

1. 启动本地 Agent 代理，再运行 `nr dev`，打开 `http://localhost:3001/agent/worlds`。
2. 点击“创建世界”，或使用“雾港停电之夜”示例。设置世界背景、规则、自己的角色和 2～6 位 Agent。
3. 可在配置面板获取代理模型，或执行一次连接测试。保存配置、创建房间都不会生成内容。
4. 进入房间后发送第一句话，或点击“让系统开启故事”。房间内置可见的“系统 · 故事主持人”，负责旁白、场景事件和安排角色；普通发言无需 @，系统会根据语义选择回应者。系统和角色逐条发言，回复完成后立即安排下一条，不额外插入固定阅读停顿；需要慢慢阅读时可暂停或使用“仅下一条”。
5. 输入 `@` 或点击成员的“点名”按钮，被点名角色按选定顺序优先回应，之后自动接续剧情。点名仍为公共消息。
6. 随时暂停或插话。“仅下一条”完成一条后暂停；手动暂停时普通发送只存档，“发送并继续”才恢复生成。调度器等待用户决定时，正常发送决定即可继续故事。
7. 暂停后可修改设定、固定公共事实、禁用角色或切换模型。已开始的世界不增减角色，可复制配置创建新的世界。
8. 世界列表可删除存档；房间的“设定”面板提供对话导出、完整备份、复制和结束故事。完整备份包含角色私有信息，不包含 API 密钥或模型推理文本。

世界预设与角色预设可以独立保存。选择已有预设后可修改并更新；创建房间时保存配置快照，之后修改预设不会改变已有房间。导入完整备份时创建新房间、新消息 ID，不覆盖现有存档；摘要从公共历史重新整理，运行不会自动恢复。

## 服务端配置

配置均只在服务端读取，示例见根目录 `.env.example`：

- `GROUP_CHAT_BASE_URL`：默认 `http://127.0.0.1:3425/v1`。
- `GROUP_CHAT_API_KEY`：默认使用用户本机代理示例中的开发密钥 `magpie`；接入其他代理时设置对应密钥。
- `GROUP_CHAT_DIRECTOR_MODEL`：可选。未设置时调度器使用候选角色的模型。
- `GROUP_CHAT_DATABASE_URL`：默认 `file:./db/group-chat.db`，与现有 Mastra 单聊数据库分开。
- `GROUP_CHAT_DATABASE_TOKEN`：可选，远程 libSQL 存储使用。

角色模型默认 `cursor/auto`，可在配置表单中修改。浏览器通过同源 API 访问，服务端使用 OpenAI SDK 调用代理；无需浏览器跨域访问本地代理。

运行基线是单个常驻 Node 进程。远程部署时 `127.0.0.1` 指向服务器自身；必须配置服务器可达的代理及持久化数据库。关闭页面/断开连接会取消运行，进程崩溃的运行在租约过期后标为中断，不自动续跑。

## 实现边界

- 单房间一个真人、2～6 个 Agent，同一公共场景；当前没有多真人协作、私聊、历史分支、媒体生成或工具执行。
- 房主能查看全部角色设定。“秘密”指角色之间的模型输入隔离，不是对房主保密。
- 明确称呼某位角色，或主角紧接着回答该角色的问题时，直接由对应角色承接；对象不明确、涉及兴趣参与时再使用模型选择。不强制角色轮换；模型失败时采用确定性兜底。选人调用最多等待 8 秒，超时取消该调用并使用现有公平性兜底继续发言；显式点名优先且跳过调度模型，之后恢复自动选人；角色的私有目标仍只传给本人。
- 主持人可选择角色发言并给出推进方向、叙述场景进展，或向玩家提出明确的选择问题。新发言不能直接进入“0 条回复就等待”，连续旁白会让位给角色；只有明确提问才等待用户决定。普通追问允许原角色继续回应。明确向主角提问后，提问者进入等待，不在兜底调度中自行续答；模型可以安排一次追问，其他角色仍可参与相关话题。问题已经展示时直接等待，不再重复生成系统提问。调度器可直接返回最终旁白正文，省去一次重复生成；兼容仅返回旁白方向的响应。角色默认提示为 50～120 字、旁白 40～90 字，以短回合推进。
- 主持人消息使用独立的 `narrator` 类型，进入公开历史和摘要，支持中断、重试与导出；配置变更等 `system` 通知仍不进入剧情。系统不读取角色秘密或私有目标。
- 新示例由系统负责合理的行动结果，用户保留自身行动和重大选择权；已有世界的自定义规则不会被自动覆盖。
- 页面通过同一可取消订阅接续有界运行，`maxTurns` 保留为每批大小，不再作为故事的自动停止条件。只有上一批正常完成时才接续；单步、重试、等待用户、异常和离开页面均不自动续跑。续跑绑定上一运行 ID，暂停还会封锁尚未到达服务端的请求，避免迟到请求重新启动故事。
- 每轮最多 180 秒、25 次调用，单个请求最多 60 秒、30 秒无事件超时；角色正文上限 2,000 字符。应用取消不等于代理上游一定停止计费。
- 使用公共历史滚动摘要，并保留原始消息；未完成片段不进入后续上下文。输入采用保守的字符预算，不声称精确匹配所有模型的 token 窗口。配置过长会暂停并提示缩减。
- 成功消息在事务提交后才标为完成。生成中的片段定期保存；服务骤停时最后一个检查点之后的未提交片段可能丢失。数据库失败会终止调度并保留可恢复片段；目前没有独立的“仅重试保存”队列。
- 角色输出为模型生成，世界规则属于叙事约束；暂停、预算、访问权限和上下文资料过滤由程序控制。
- 首次读取最多返回 100 条消息，页面可继续加载更早历史。首版本机存档采用房间 JSON 文档加事务、请求幂等表和运行租约；不是面向大规模多人系统的分布式事件存储。
- 管理与流式接口统一使用 Route Handlers，避免给仅此页面使用的能力同时维护两套 HTTP/tRPC 契约；原有单聊 tRPC 不变。

## 代码与验证

- 页面与表单：`src/app/agent/worlds/`。
- API：`src/app/api/group-chat/[[...path]]/route.ts`，包含鉴权、来源和房间所有权校验。
- 领域、上下文、存储和调度：`src/lib/group-chat/`。
- 传输：复用共享 `useChatStreamCore`，使用 AI SDK 的 SSE 解析器读取房间事件；OpenAI SDK 负责代理协议。
- `nr test:group-chat`：存档、权限、上下文隔离、自动调度与连续接续、点名优先、幂等、回复之间暂停、取消竞态、摘要和协议边界测试。
- `nr check`：代码规范检查。
- `node_modules/.bin/tsc --noEmit --incremental false`：类型检查。

本次已验证最小真实代理文本调用，以及新增列表页、房间页、API 的开发编译。UI 由用户手工验收；未执行 headless Chrome 或生产构建，也未将模型生成质量视为由单元测试保证。
