# 剧本模式产品迭代

剧本模式是多人设对白台。调度器按规则选人，NPC 与可选旁白用对白接续；操作者在故事外干预，也可以代替某个角色或旁白写一条。房间、消息和摘要保存在服务端。系统不代替操作者决定何时暂停、重试或改设定。

迭代只服务这四件事：

1. 看清故事停在哪：谁刚说了、是否暂停、摘要盖了多远、本批还剩几条。
2. 用更短的操作干预或代写：系统 / 旁白 / 角色身份、点名、继续 / 仅下一条 / 重试。
3. 已生成的对白与旁白在操作者确认前不丢；失败、中断、截断可接着处理，不重开整场。
4. 改设定或人选时保留已发生的公开历史；需要换卡司时用复制世界，而不是清档重写。

新特性、功能优化、界面优化都可以进入下表。不服务上面四件事的需求不进入下表。行为细节以 [剧本模式](./group-chat.md) 为准。本表只记录迭代和状态。

状态只有三种：

| 状态 | 含义 |
| --- | --- |
| 已交付 | 行为已经在当前提交的产品里 |
| 已实现 | 工作区里已有代码，对应验收已过，还没提交，或还没在浏览器里走过 |
| 未开始 | 已列入表，还没有改代码 |

状态变化时改原行，不另起一行。

| 编号 | 类型 | 迭代 | 对应定位 | 状态 |
| --- | --- | --- | --- | --- |
| S1 | 新特性 | 多 NPC 对白接续，旁白可选；创建后自动开场，导入备份保持暂停 | 操作者决定何时推进 | 已交付 |
| S2 | 新特性 | 系统 / 旁白 / 角色身份输入，支持点名；运行中提交会中止当前批再开新批 | 用更短的操作干预或代写 | 已交付 |
| S3 | 新特性 | 自动批次、仅下一条、暂停、对失败 / 中断 / 截断消息重试 | 失败可接着处理，不重开整场 | 已交付 |
| S4 | 新特性 | 规则选人与旁白时机；公开历史摘要压缩上下文 | 看清谁该说、摘要盖了多远 | 已交付 |
| S5 | 新特性 | 角色上下文隔离；修改设定保留公开历史并清空摘要后重整理 | 改设定不重写已发生历史 | 已交付 |
| S6 | 新特性 | 导出对话 / 旁白 Markdown、完整 JSON 备份、复制世界、结束故事 | 记录可离开房间，换卡司不靠清档 | 已交付 |
| S7 | 新特性 | 世界模板、世界 / 角色预设、大厅筛选与导入存档 | 更快开一场或复用设定 | 已交付 |
| S8 | 功能优化 | 截断 / 失败 / 中断消息在对话流里直接露出「重试」，不必先找顶栏 | 失败可接着处理 | 未开始 |
| S9 | 功能优化 | 运行中断开或租约过期后，顶栏与消息列表一眼对上已落盘片段和暂停原因 | 看清故事停在哪，已生成内容不丢 | 未开始 |
| S10 | UI优化 | 上下文将满时在侧栏提示可操作下一步（缩设定 / 导出），不只在开跑时报错 | 看清还能推多远再决定操作 | 未开始 |
