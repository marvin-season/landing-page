# 开放世界：小说模式

## 1. 核心决策

一个 Writer 统一负责情节、人物言行、叙事视角、文风和章节衔接。角色是作者掌握的创作资料，不是轮流调用的 Agent。写章、润色、剧情整理和背景总结都是同一个 `world-writer` 的不同任务，靠不同的 system 指令区分。

| 项目 | 剧本 | 小说 |
| --- | --- | --- |
| 产物 | 按顺序发生的对白与旁白消息 | 按章排列的连续正文 |
| 生成职责 | 调度器选人，actor / narrator / summary 分工 | 一个 Writer |
| 人物私有资料 | 按角色隔离 | 作者全部可见，按剧情揭示 |
| 推进方式 | 自动接续多批 | 作者每次触发一个任务，不自动连写 |
| 正文存档 | 服务端房间 | 当前浏览器 IndexedDB |
| 生成接口 | `POST /api/group-chat/rooms/:id/runs` | `POST /api/novel` |

## 3. 设定来源

```ts
type Chapter = { id: string; title: string; text: string };

type Novel = {
  title: string;
  style: string;
  outline: string;
  chapterGoal: string; // 下一章要求
  words: string; // 每章目标字数（表单字符串）
  chapters: Chapter[]; // 数组顺序即章节顺序
  checkpoint?: { throughChapterId: string; summary: string }; // 续写摘要
  background?: ImportedNovelBackground; // 当前无写入入口
};
```

- **首次打开**：本机没有记录时，用 `createNovel(config)` 初始化：书名取世界名称，大纲取 `storyGoal`，文风为默认的第三人称，每章 4000 字。
- **修改设定**：在顶栏「设定」中修改。小说房间的编辑器把「故事推进要求」换成「创作设定」，包括小说名称（≤100）、文风与叙述视角、大纲与创作要求（≤12000）。保存时先写入本机小说，再把大纲截取前 4000 字写入 `config.storyGoal`，然后 `configure` 世界配置。
- **在大厅创建小说时**：本机还没有小说记录，编辑器只显示「大纲与创作要求」，内容写入 `storyGoal`，首次打开时再据此初始化。
- **下一章要求与每章目标字数**：在阅读页底部填写，目标字数范围为 1000～8000，随每次输入保存到本机。
- **生成时读取**：每次生成都读取当前 `room.config` 和本机小说。修改设定只影响之后的生成，不会改写已有章节。
- **写作模型**：使用第一个启用角色的模型，全部禁用时用第一个角色的模型。小说编辑器里角色的启用开关显示为「候选写作模型」，启用状态不影响角色资料是否交给 Writer。小说房间可以随时增减角色。

## 4. Writer 任务与上下文

请求体为 `{ roomId, prompt, task }`，`task` 取 `chapter`、`rewrite` 或 `summary`。`prompt` 是在浏览器中构造的 JSON 文本，服务端按 `task` 选择对应的固定指令。

- **完整世界设定**：整个 `WorldConfig`。
- **世界基本设定**：`title`、`background`、`scene`、`rules`、`facts`、`storyGoal`、`characters`，不含 `priorContext`。

两者都包含全部角色的全部资料。剧本消息和剧本摘要都不会发给 Writer。

| 功能 | task | 发送的上下文 |
| --- | --- | --- |
| 续写下一章 | `chapter` | 完整世界设定；书名、文风、大纲；已完成章节的标题和正文；`task` 含章号、目标字数、8000 字上限和下一章要求（留空时为“承接前文与大纲，推进下一阶段情节。”）。有效的续写摘要以 `archivedChapters` 代替它覆盖的章节。 |
| 剧情插入 | `chapter`，`task.mode: "insert"` | 完整世界设定；书名、文风、大纲；插入点之前的章节（`previousChapters`）和之后的章节（`followingChapters`），章号和默认标题按插入后的位置编号；插入要求。插入点在摘要范围之后时使用摘要。整体超过 150,000 字符时只保留插入点两侧各一章，仍超限则报错。 |
| 润色整章 | `rewrite` | 世界基本设定；目标章（章号、标题、正文）；全部前文章节和紧邻的下一章；润色要求（留空时为“改善语言、节奏和过渡，保留关键剧情。”）。开启「精简上下文」后，章节部分只发本章正文。 |
| 润色选段 | `rewrite` | 世界基本设定；目标章的章号和标题，以及当前编辑草稿中的 `selection: { before, text, after }`；替换长度上限为 8000 减去选区外文字的长度。不发送其他章节。开启「精简上下文」后只发选段正文。 |
| 剧情粘合 | `rewrite`，`task.mode: "stitch"` | 完整世界设定；书名、文风、大纲；前一章结尾和后一章开头（各约 1,200 字符，边界对齐到段落或句末，短章取全文），以 JSON `{ ending, opening }` 放入 `targetChapter.text`；两段改写区之外紧邻的原文（各 ≤600 字符）；选中范围外前一章的结尾、后一章的开头（各 ≤600 字符）；过渡要求和两段各自的长度上限。要求模型输出 JSON。 |
| 剧情合并 | `rewrite`，`task.mode: "merge"` | 完整世界设定；书名、文风、大纲；两章完整正文，以 JSON `{ first, second }` 放入 `targetChapter.text`；选中范围外前一章的结尾、后一章的开头（各 ≤600 字符）；固定的合并要求（去重、抹除接缝，保留关键事件、伏笔和人物变化），以及选填的本次写作要求。 |
| 总结并导出背景 | `summary` | 完整世界设定；书名；已完成章节的标题和正文（有效摘要会代替它覆盖的章节）。不发送文风、大纲和下一章要求。 |
| 续写分支 · 自动总结 | `summary` | 同上，但章节范围只取前 `max(1, 章节数 - 1)` 章。 |

润色、粘合和合并都不发送续写摘要。没有有效续写摘要时，写章、插入和总结会把 `background` 作为 `importedBackground` 一起发送；有有效摘要时不发送。

**不调用模型的操作**：编辑与保存正文、查看修改、删除选区、切换章节、拆章、删章、导入导出小说、应用或丢弃草稿，以及用手动填写的摘要创建分支（只创建房间并写入本机）。

## 5. Writer 接口

`POST /api/novel`（[`novel.ts`](../../src/lib/group-chat/novel.ts)）：

1. 校验登录和同源 `Origin`，以及 `roomId`、`task`，`prompt` 不超过 150,000 字符。
2. 读取房间并校验所有者。只接受 `kind === "novel"` 且未结束的房间，否则返回 409。
3. 选定写作模型，会话标识为 `worldSessionId(room, "writer", model)`。
4. 调用 `handleChatStream`：`agentId: "world-writer"`，按 task 选用 `writerInstructions` / `rewriteInstructions` / `summaryInstructions`，`activeTools: []`，`toolChoice: "none"`，`maxSteps: 1`，`maxOutputTokens: 8192`，`maxRetries: 0`，并透传 `request.signal`。
5. 以 AI SDK UI 消息流返回。客户端不能覆盖模型、指令或工具配置。

## 6. 任务生命周期

同一时刻只运行一个任务：`generating` ref 防止重复提交，生成期间整页的章节操作都处于锁定状态。

```text
start(run, prompt) → 清空草稿与错误 → stream.send(/api/novel)
  onEvent: finish 带 finishReason 且不是 stop → 报错（截断）
           非剧情整理任务把文本实时写入 preview
  onComplete: 需要已收到 finish，且正文非空，否则报错“连接提前结束或没有生成内容”
           按 run 类型处理（见下表）
stop() → 取消订阅，提示草稿未计入正文
```

| 任务 | 完成后 |
| --- | --- |
| 续写 | 输出到编辑器右栏，点「应用草稿」才保存为新章节。停止后已收到的正文仍可编辑，草稿需非空且不超过 8000 字才可保存 |
| 整章润色 | 和续写一样输出到编辑器右栏。结束或停止后可修改草稿，点「应用草稿」才替换当前章 |
| 选段润色 | `preview` 作为待应用草稿，等待用户应用或丢弃 |
| 剧情整理 | 解析为 `PlotDraft`：粘合需能解析出 JSON 的两个字段，合并 / 插入需 ≤8000 字，解析失败报错，成功后等待用户应用 |
| 背景总结 | 生成背景文件、下载、在页面预览 |
| 分支摘要 | 不超过 20,000 字时填入分支摘要框 |

**应用草稿前的校验**：本机小说对象与发起时相同，世界配置 `version` 未变，房间未结束。任一不满足时提示“已变更，请重新生成”。

**保存**（`update`）：

- 默认先更新页面，再进入串行写入队列，写入 IndexedDB。保存失败时提示先导出，内容仍留在页面。
- 编辑器保存、剧情整理应用和导入使用 `persistFirst`，写入成功后才更新页面，失败时保留原内容。
- 每次保存都会检查续写摘要是否仍然有效，见[第 8 节](#8-续写上下文与续写分支)，并清除本页的背景总结预览。

**结束故事**之后，接口拒绝所有 Writer 任务，页面也禁用续写、润色和剧情整理。手动编辑、导入和导出仍然可用。

## 7. 阅读、编辑与润色

### 阅读页

- 顶部显示已完成章数和保存状态，右侧是「导入小说」和「导出」菜单（整本 TXT、整本 Markdown、总结并导出背景）。
- 「续写上下文」显示下一次续写请求的字符数和 150,000 字符上限，以及摘要覆盖的章数。这里统计的是字符，不是模型 token。
- 章节目录选择当前章，默认显示最后一章。吸顶操作栏有：
  - 「编辑本章」
  - 「剧情整理」：至少有两章相邻且都有正文时可用。粘合、合并和插入都提供「本次写作要求」，切换方式或丢弃草稿重试时保留输入。合并可留空，粘合和插入必填。
  - 「章节操作」菜单：拆分本章、润色整章、删除本章。
- 正文可以从底部磨砂玻璃输入框后方滚过。点击「继续创作下一章」展开，填写要求、确认目标字数后点「续写下一章」；收起时保留输入。等待正文时留在阅读页，章节目录选中新章并显示「正在构思」；收到正文后再进入双栏编辑器。书名为空或每章字数无效时不能续写。续写上下文超过上限时提示导出当前卷，到新世界继续。

### 拆章与删章

- **拆章**：在只读文本中放置光标或选区起点，预览原章结尾和新章开头，两侧都要有正文。新章插在后面，标题为默认编号；后续章节的默认标题（如“第3章”）会重新编号，自定义标题保持不变。
- **删章**：确认后删除，其余章节的标题不变。

### 编辑模式（`ChapterEditor`）

- **双栏**：左栏「稳定版本」是已保存正文（只读），右栏「编辑草稿」可修改，并显示字数和 8000 字上限。
- **生成新章**：左栏为空，右栏接收正文。生成中草稿只读，可以停止生成或向上滚动查看已生成的内容。滚回末尾后恢复自动跟随。结束或停止后可编辑草稿，也可在右栏底部修改要求后重新生成。「应用草稿」首次保存成功后，左栏更新并留在当前章的编辑页。
- **保存**：「保存章节」写入成功后，草稿成为新的稳定版本；失败则保留草稿并标记“保存失败”。超过上限时不能保存。
- **生成草稿备份**：续写和整章润色从收到正文起，在当前浏览器按账号和作品备份右栏，手动修改也会备份。刷新后回到同一作品会自动恢复草稿，生成不会接着运行。成功应用草稿或确认丢弃后会清除备份。
- **查看修改**：按行对比稳定版本和当前草稿，可以直接在对比页保存或应用草稿。两边行数之积超过 200 万时，退化为整段删除加整段新增。
- **切换章节**：草稿有未保存修改、正在保存、正在润色或有待应用的润色草稿时，目录不可切换。
- **离开保护**：有未保存修改时，离开页面或「返回阅读」都会提示确认。

### 润色

- **选段润色**：在右栏划选正文后出现润色面板，可以填写指令（可选），用「精简上下文」开关和「删除选区」按钮。生成时隐藏指令框，流式显示草稿；完成后「应用替换」只替换选中的那段原文位置（即使正文中有重复句子），改动写进右栏草稿并高亮，仍需「保存章节」才会保存。修改正文或改变选区会丢弃当前润色。
- **整章润色**：在阅读页从「章节操作」进入，填写指令后点「开始润色」，立即进入双栏编辑器。左栏显示原文，右栏等待输出，收到正文后逐步显示草稿。可停止生成、滚动阅读、修改草稿、查看差异，或修改要求后重新生成。「应用草稿」保存成功后留在编辑页，返回阅读时高亮已替换的范围。
- **默认上下文超限**：提示开启「精简上下文」；精简后仍超限，则提示缩短正文或设定。
- **离开保护**：生成中或有待应用的草稿时，离开页面会提示确认。

## 8. 续写上下文与续写分支

「创建续写分支」打开抽屉，用剧情摘要压缩前 `max(1, 章节数 - 1)` 章，在新房间继续写作。

1. 「自动总结」调用 `summary` 任务生成摘要；也可以手动填写或修改，不超过 20,000 字。总结请求本身超限时只能手动填写。
2. 页面实时计算压缩前后续写请求的字符数。只有压缩后变短，且不超过 150,000 字符，才允许创建。
3. 创建时用 `世界名称 · 续写分支`（总长 ≤60）作为标题，以 `POST rooms` 新建 `kind: "novel"` 房间，再把小说完整复制到新键下，并写入 `checkpoint: { throughChapterId, summary }`。本机写入失败时会删除刚建的房间。成功后跳转到新房间。
4. 原小说不改动。新房间 ID 不同，所以使用新的 Writer 会话。

**摘要的使用**：分支保留全部正文，阅读和导出都不受影响。续写、插入和总结时，用 `archivedChapters: { throughChapter, summary }` 代替被覆盖的章节，未覆盖的章节照常发送原文。插入点的前一章仍在摘要范围内时，改用原文，以便衔接上下文。在分支里再创建分支时，会把已有摘要和后续章节合并成新的摘要。

**摘要失效**：被覆盖的任一章节被编辑、删除、拆分、合并或移动，或者摘要指向的章节已不存在，摘要就会被清除，之后恢复发送原文。

## 9. 导入、导出与背景总结

**导出小说**：直接读取页面中的章节，不等待保存完成，所以也是本机写入失败时保留成稿的方式。文件名中的非法路径字符替换为 `_`。

- TXT：第一行是书名；没有章号的标题补上“第 N 章”；正文中与章标题格式相同的行加反斜杠转义。
- Markdown：`# 书名`，每章 `## 标题`，正文原样输出。
- 不包含草稿、创作设定、角色资料和续写摘要。

**导入小说**：接受 ≤2 MB 的 `.txt` 或 `.md`，确认覆盖后才会写入。

- TXT：每章以单独一行的“第 N 章”开头（支持中文数字，可带分隔符和副标题）。第一章之前的单独一行如果与文件名一致、用书名号括起，或后面紧跟第一章，就作为书名。读取时还原转义的行。带章号的章节即使超过 8000 字也不拆分。
- Markdown：文件开头的 `#` 标题（不是章号格式时）作为书名；`##` 标题，或任意级别中形如“第 N 章 / 节 / 回 / 集”“Chapter N”的标题，作为章节分隔。
- Markdown 的章节，以及 TXT 第一章之前没有章号的正文，超过 8000 字时会按段落或行拆成多段，标题加“（续 N）”。
- 拒绝空文件、二进制内容和背景总结文件。
- 保存成功后整本替换：书名与章节换成导入内容，文风、大纲、字数和下一章要求重置为默认值，清除续写摘要和草稿。世界设定不变。保存失败时原小说保持不变。

**总结并导出背景**：

- 需要至少一章。生成成功后下载 `书名-背景总结.md`，同时在页面显示总结，可以「再次导出总结」。任何保存都会清除这份预览。
- 文件结构：
  - 标题：`# 书名 · 背景总结（截至第 N 章）`
  - 正文：可阅读的 Markdown 总结
  - 末尾：`<!-- novel-background … -->` 注释，内含 `format: "novel-background"`、`schemaVersion: 1`、`source`（书名、章数、最后一章 ID）、`createdAt` 和完整世界配置（含角色私有资料）
- 这个文件可以导入到任意世界的「前置剧情」，导入时只取正文。

## 10. 已知限制

- 小说只保存在当前浏览器。清除浏览器数据、换浏览器或换设备后无法恢复；删除房间不会清理本机记录；复制世界、JSON 备份都不包含章节。
- 没有跨标签页写入协调。多个标签页同时编辑同一本小说时，最后写入的会覆盖之前的。
- 生成草稿的备份只在当前浏览器。选段润色和剧情整理的待应用预览仍只在内存中。保存失败后没有单独的“重试保存”，下一次成功写入会保存整本当前内容。
- 浏览器取消会传到服务端和代理，但上游是否立即停止计算或计费，由代理和模型决定。
- 输出上限为 8192 tokens，目标字数较大时仍可能被截断，截断的结果不会保存。
- 导出和背景总结不会做语义脱敏，模型写进正文的秘密会原样导出。
