# 开放世界：小说模式

## 1. 核心决策

一个 Writer 统一负责情节、人物言行、叙事视角、文风和章节衔接。角色是作者掌握的创作资料，不是轮流调用的 Agent。写章、润色、剧情整理和背景总结都是同一个 `world-writer` 的不同任务，靠不同的 system 指令区分。

| 项目 | 剧本 | 小说 |
| --- | --- | --- |
| 产物 | 按顺序发生的对白与旁白消息 | 按章排列的连续正文 |
| 生成职责 | 调度器选人，actor / narrator / summary 分工 | 一个 Writer |
| 人物私有资料 | 按角色隔离 | 作者全部可见，按剧情揭示 |
| 推进方式 | 自动接续多批 | 作者每次触发一个任务，不自动连写 |
| 正文存档 | 服务端房间 | 当前浏览器 IndexedDB |
| 生成接口 | `POST /api/group-chat/rooms/:id/runs` | `POST /api/novel` |

## 3. 设定来源

```ts
type Chapter = { id: string; title: string; text: string; brief?: string };

type Novel = {
  title: string;
  style: string;
  outline: string;
  chapterGoal: string; // 下一章要求
  words: string; // 每章目标字数（表单字符串）
  chapters: Chapter[]; // 数组顺序即章节顺序
  checkpoint?: { throughChapterId: string; summary: string }; // 续写摘要
  background?: ImportedNovelBackground; // 当前无写入入口
};
```

- **首次打开**：本机没有记录时，用 `createNovel(config)` 初始化：书名取世界名称，大纲取 `storyGoal`，文风为默认的第三人称，每章 4000 字。开发模式下，若该作品目录里有 TXT，再用其中最新一份的书名和章节覆盖正文；文风、大纲、每章字数和下一章要求仍用本机记录或上述默认值。正文与本机一致的章节保留原 id。
- **修改设定**：在顶栏「设定」中修改。小说房间的编辑器把「故事推进要求」换成「创作设定」，包括小说名称（≤100）、文风与叙述视角、大纲与创作要求（≤12000）。保存时先写入本机小说，再把大纲截取前 4000 字写入 `config.storyGoal`，然后 `configure` 世界配置。
- **在大厅创建小说时**：本机还没有小说记录，编辑器只显示「大纲与创作要求」，内容写入 `storyGoal`，首次打开时再据此初始化。
- **下一章要求与每章目标字数**：在阅读页底部填写，目标字数范围为 1000～8000，随每次输入保存到本机。
- **本章要求**：续写开始时，若「下一章要求」去掉空白后还有内容，就记下这段文字。应用该次草稿时写入新章的 `brief`。同一章草稿重新生成后，以最后一次实际送出的要求为准；要求留空则不保留 `brief`。润色、剧情整理、导入、手动保存和从服务器同步都不会新写 `brief`。它只留在本机小说里，不进入 Writer 上下文，也不写入 TXT / Markdown。
- **生成时读取**：每次生成都读取当前 `room.config` 和本机小说。修改设定只影响之后的生成，不会改写已有章节。
- **写作模型**：使用第一个启用角色的模型，全部禁用时用第一个角色的模型。小说编辑器里角色的启用开关显示为「候选写作模型」，启用状态不影响角色资料是否交给 Writer。小说房间可以随时增减角色。

## 4. Writer 任务与上下文

请求体为 `{ roomId, prompt, task }`，`task` 取 `chapter`、`rewrite` 或 `summary`。`prompt` 是在浏览器中构造的 JSON 文本，服务端按 `task` 选择对应的固定指令。

- **完整世界设定**：整个 `WorldConfig`。
- **世界基本设定**：`title`、`background`、`scene`、`rules`、`facts`、`storyGoal`、`characters`，不含 `priorContext`。

两者都包含全部角色的全部资料。剧本消息和剧本摘要都不会发给 Writer。

| 功能 | task | 发送的上下文 |
| --- | --- | --- |
| 续写下一章 | `chapter` | 完整世界设定；书名、文风、大纲；只发送当前章及之前章节的标题和正文；`task` 含新章章号、目标字数、8000 字上限和下一章要求（留空时为“承接前文与大纲，推进下一阶段情节。”）。续写摘要仅在覆盖范围不超过当前章时使用。 |
| 剧情插入 | `chapter`，`task.mode: "insert"` | **第一章之前**：只发送世界基本设定、书名、文风、大纲及本次写作要求和字数限制，不发送已有章节或剧情摘要。**章间**：发送完整世界设定、书名、文风、大纲、插入要求、字数限制及所选两章的完整正文（`previousChapters` / `followingChapters` 各一章）。章号和默认标题按插入后的位置编号。超过 150,000 字符则报错。 |
| 润色整章 | `rewrite` | 世界基本设定；目标章（章号、标题、正文）；全部前文章节和紧邻的下一章；润色要求（留空时为“改善语言、节奏和过渡，保留关键剧情。”）。开启「精简上下文」后，章节部分只发本章正文。 |
| 润色选段 | `rewrite` | 世界基本设定；目标章的章号和标题，以及当前编辑草稿中的 `selection: { before, text, after }`；替换长度上限为 8000 减去选区外文字的长度。不发送其他章节。开启「精简上下文」后只发选段正文。 |
| 剧情粘合 | `rewrite`，`task.mode: "stitch"` | 完整世界设定；书名、文风、大纲；所选前一章的结尾和后一章的开头（各约 1,200 字符，边界对齐到段落或句末，短章取全文），以 JSON `{ ending, opening }` 放入 `targetChapter.text`；所选两章中紧邻改写区的保留原文（各 ≤600 字符）；过渡要求和两段各自的长度上限。要求模型输出 JSON。 |
| 剧情合并 | `rewrite`，`task.mode: "merge"` | 完整世界设定；书名、文风、大纲；所选连续章节的章名和完整正文，按章序以 JSON 数组放入 `targetChapter.text`；选中范围外前一章的结尾、后一章的开头（各 ≤600 字符）；固定的单章压缩要求（去重、抹除接缝，保留关键事件、伏笔和人物变化），以及选填的本次写作要求。超过 150,000 字符则报错。 |
| 总结并导出背景 | `summary` | 完整世界设定；书名；已完成章节的标题和正文（有效摘要会代替它覆盖的章节）。不发送文风、大纲和下一章要求。 |
| 续写上下文压缩 | `summary` | 完整世界设定、书名、已有摘要或导入背景、本批待压缩的正文，以及按压缩率计算的累计摘要目标字符数和选填的压缩提示词。多批次依次更新同一份剧情摘要。 |

润色和剧情整理都不发送续写摘要。续写和总结在没有有效续写摘要时会发送导入背景；章间插入有导入背景时也会发送。导入背景以 `importedBackground` 字段传递。

**不调用模型的操作**：编辑与保存正文、查看修改、删除选区、切换章节、拆章、删章、导入导出小说、应用或丢弃草稿，以及复制小说（只创建房间并写入本机）。

## 5. Writer 接口

`POST /api/novel`（[`novel.ts`](../../src/lib/group-chat/novel.ts)）：

1. 校验登录和同源 `Origin`，以及 `roomId`、`task`，`prompt` 不超过 150,000 字符。
2. 读取房间并校验所有者。只接受 `kind === "novel"` 且未结束的房间，否则返回 409。
3. 选定写作模型，会话标识为 `worldSessionId(room, "writer", model)`。
4. 调用 `handleChatStream`：`agentId: "world-writer"`，按 task 选用 `writerInstructions` / `rewriteInstructions` / `summaryInstructions`，`activeTools: []`，`toolChoice: "none"`，`maxSteps: 1`，`maxOutputTokens: 8192`，`maxRetries: 0`，并透传 `request.signal`。
5. 以 AI SDK UI 消息流返回。客户端不能覆盖模型、指令或工具配置。

## 6. 任务生命周期

同一时刻只运行一个任务：`generating` ref 防止重复提交，生成期间整页的章节操作都处于锁定状态。

```text
start(run, prompt) → 清空草稿与错误 → stream.send(/api/novel)
  onEvent: finish → 记下是否截断（finishReason 不是 stop）；非剧情整理任务把文本实时写入 preview
  onComplete: 需要已收到 finish，且正文非空，否则报错“连接提前结束或没有生成内容”
           截断且已有正文时：续写 / 润色 / 可解析的剧情整理保留可编辑草稿并标明未写完；摘要截断不采用
           按 run 类型处理（见下表）
  stop() → 取消订阅；续写 / 整章润色保留已收到正文，其余提示草稿未计入正文
```

| 任务 | 完成后 |
| --- | --- |
| 续写 | 输出到编辑草稿，点「应用草稿」才在续写起点之后插入新章，并带上这次送出的本章要求。原有后文保留，后续默认章号顺延。停止后已收到的正文仍可编辑，草稿需非空且不超过 8000 字才可保存。刷新后恢复的续写草稿仍记住这次要求 |
| 整章润色 | 和续写一样输出到编辑草稿。结束或停止后可修改草稿，点「应用草稿」才替换当前章 |
| 选段润色 | `preview` 作为待应用草稿，等待用户应用或丢弃 |
| 剧情整理 | 解析为 `PlotDraft`：粘合需能解析出 JSON 的两个字段，合并 / 插入需 ≤8000 字，解析失败报错，成功后等待用户应用 |
| 背景总结 | 生成背景文件、下载、在页面预览 |
| 分支摘要 | 不超过 20,000 字时填入分支摘要框 |

**应用草稿前的校验**：本机小说对象与发起时相同，世界配置 `version` 未变，房间未结束。任一不满足时提示“已变更，请重新生成”。

**保存**（`update`）：

- 默认先更新页面，再进入串行写入队列，写入 IndexedDB。保存失败时提示先导出，内容仍留在页面。
- 编辑器保存、剧情整理应用和导入使用 `persistFirst`，写入成功后才更新页面，失败时保留原内容。
- 每次保存都会检查续写摘要是否仍然有效，见[第 8 节](#8-续写上下文与-fork)，并清除本页的背景总结预览。

**结束故事**之后，接口拒绝所有 Writer 任务，页面也禁用续写、润色和剧情整理。手动编辑、导入和导出仍然可用。

## 7. 阅读、编辑与润色

### 阅读页

- 房间顶栏在空闲时显示已完成章数，保存中则加上「正在保存…」。阅读区不再单独放「小说创作」标题。房间顶栏的「文件」菜单包含导入小说、Fork、导出整本 TXT、导出整本 Markdown 和总结并导出背景。
- 房间顶栏的「提示词历史」按最新在前显示已提交的非空续写、润色和剧情整理要求。记录按账号和作品独立保存在当前浏览器，不进入 Writer 上下文，也不随小说导入、导出或复制。续写记录可以「填入下一章要求」，效果与阅读页的「用作下一章要求」相同。润色整章记录会打开该章编辑页并展开底部「润色本章」；已在编辑页且未划选时，直接填入该输入框。选段润色记录仅在编辑页已划选且等待输入时填入。剧情粘合 / 合并 / 插入记录会打开剧情整理并填入对应「本次写作要求」。均不自动提交。
- 房间顶栏的「上下文」与「文件」并列，显示从书末续写的请求大小，可压缩上下文或展开查看已保存的摘要。
- 章节用分页切换，默认停在最后一章。吸顶栏是分页：上一章、章号、下一章。不超过 5 章时列出全部章号；超过 5 章后最多同时显示 5 个章号，保留第一章、最后一章和当前章两侧的相邻章号，跳过的章号收成省略号。章节末尾是「上一章」「下一章」。省略号不紧贴当前章：点到紧挨省略号的章号后，窗口会挪开，把当前章和相邻章展开。点击省略号打开下拉，格子里是被收起的章号，顶部显示指向的章名，点选后切到该章。当前章高亮，悬停章号可看章名。正在构思的新章排在最后，用虚线框标出。切章时，章首已在视口内则保持滚动位置，否则回到章首；短章也保留足够的阅读区高度，避免顶栏跳动。新章内容轻微上移并淡入，系统启用减少动态效果时直接显示。阅读页未聚焦输入框时，可用 ← / → 切换。正在构思、润色或导入时不可切换。吸顶操作栏把分页、本章字数和操作按钮排在同一行；窄屏时分页单独占一行。栏内显示当前章字数和每章目标字数（正文字符数，与编辑器相同；目标字数无效时只显示本章字数；本章不足目标 75% 时标「偏短」），并有：
  - 「编辑本章」
  - 「章节操作」菜单：拆分本章、剧情整理、删除本章。粘合和章间插入需选择相邻且都有正文的两章。合并可向两端扩选至少两章连续且有正文的章节，确认后以一章替换所选范围，后续默认章号随位置调整。合并正文最多 8,000 字，可能大幅缩短；预览显示原文总字数与草稿字数。「剧情插入」也可选择「第一章之前」，只需已有一章，无需该章有正文。粘合、合并和插入都提供「本次写作要求」，切换方式或丢弃草稿重试时保留输入。合并可留空，粘合和插入必填。
    章节格只显示章号，悬停可看章名。草稿生成后收起设置区；丢弃草稿后回到原选择和写作要求。
- 正文可以从底部磨砂玻璃输入框后方滚过。点击「继续创作下一章」展开，小字会显示接在哪一章之后以及新章章号；空书从第 1 章起写，阅读区提供「填写下一章要求」一键展开并聚焦输入。填写要求、确认目标字数后点「AI 续写」；按钮带魔杖图标。同一行旁边是「手动写下一章」，直接打开空白新章，不调用模型。保存后才插入当前续写起点之后，不写入本章要求。故事已结束时仍可手动开写。正在构思、润色或导入时两个入口都不可用。收起时保留输入。等待正文时留在阅读页，分页停在新章并用虚线框标出；收到正文后再进入编辑器。书名为空或每章字数无效时不能续写。续写上下文超过上限时提示导出当前卷，到新世界继续。
- 阅读页章名可直接修改。点章名进入编辑，回车或离开输入框后保存，最多 80 字；留空则恢复当前位置的默认编号。只匹配「第N章」的标题在拆章、插入后仍按新位置重编号，其他标题保持不变。删章不改其余章节的标题。正在构思、润色或导入时不能改章名。
- 当前章有本章要求时，标题下显示原文和「用作下一章要求」。点击后把这段文字写入底部「下一章要求」，展开输入框并聚焦，不开始生成。正在构思、润色、导入或故事已结束时不能填入。提示词历史里的续写记录使用同一动作。

### 拆章与删章

- **拆章**：在只读文本中放置光标或选区起点，预览原章结尾和新章开头，两侧都要有正文。新章插在后面，标题为默认编号；后续章节的默认标题（如“第3章”）会重新编号，自定义标题保持不变。
- **删章**：确认后删除，其余章节的标题不变。

### 编辑模式（`ChapterEditor`）

- **编辑草稿**：只显示可修改的草稿，在页面中居中，并显示字数和 8000 字上限。已保存正文不在编辑页并列展示。
- **底部润色**：编辑页底部有与阅读页相同的磨砂输入条。默认收起为「润色本章」，展开后填写润色指令（选填）和「精简上下文」，点「开始润色」。划选正文后，同一条输入改为「润色选段」，并可删除选区。续写新章时不显示这条输入，仍用章内的重新生成表单。
- **生成新章**：草稿区接收正文。生成中草稿只读，可以停止生成或向上滚动查看已生成的内容。滚回末尾后恢复自动跟随。结束或停止后可编辑草稿，也可在草稿区底部修改要求后重新生成。「应用草稿」首次保存成功后留在当前章的编辑页。
- **手动开写下一章**：从阅读页底部「手动写下一章」进入。草稿区为空，自行撰写，目录中显示为「新章」。点「保存章节」后才插入续写起点之后。未输入正文时可以直接返回。不调用模型，不写入本章要求，也不进入生成草稿备份。
- **保存**：「保存章节」写入成功后，草稿成为新的稳定版本；失败则保留草稿并标记“保存失败”。超过上限时不能保存。
- **生成草稿备份**：续写和整章润色从收到正文起，在当前浏览器按账号和作品备份编辑草稿，手动修改也会备份。续写草稿同时记录续写起点。选段润色与剧情整理在生成出待应用结果后也会备份。刷新后回到同一作品会自动恢复草稿或待应用结果，生成不会接着运行。成功应用或确认丢弃后会清除备份。
- **查看修改**：按行对比稳定版本和当前草稿，可以直接在对比页保存或应用草稿。两边行数之积超过 200 万时，退化为整段删除加整段新增。
- **切换章节**：草稿有未保存修改、正在保存、正在润色或有待应用的润色草稿时，目录不可切换。
- **离开保护**：有未保存修改时，离开页面或「返回阅读」都会提示确认。

### 润色

- **选段润色**：在编辑草稿中划选正文后，底部输入条改为「润色选段」，交互与「润色本章」相同。发给模型的上下文仍是选段：`selection: { before, text, after }`，精简上下文时只发选段正文。生成时输入条展开并流式显示替换草稿；完成后「应用替换」只替换选中的那段原文位置（即使正文中有重复句子），改动写进编辑草稿并高亮，仍需「保存章节」才会保存。修改正文或改变选区会丢弃当前选段润色。「删除选区」直接删掉划选文字。
- **整章润色**：在编辑页展开底部「润色本章」，填写指令后点「开始润色」。草稿区等待输出，收到正文后逐步显示草稿。可停止生成、滚动阅读、修改草稿、查看差异，或修改要求后重新生成。「应用草稿」保存成功后留在编辑页，返回阅读时高亮已替换的范围。阅读页不再提供「润色整章」。
- **默认上下文超限**：提示开启「精简上下文」；精简后仍超限，则提示缩短正文或设定。
- **离开保护**：生成中或有待应用的草稿时，离开页面会提示确认。

## 8. 续写上下文与 Fork

整本正文存在本机 IndexedDB，没有 150,000 字符的整本上限，实际可用量取决于浏览器存储。续写检查序列化后的 `prompt` 长度（最多 150,000 个 UTF-16 码元）以及完整请求体编码后的大小（前端预算 384 KiB）。模型自己的窗口按 token 计算，另计固定指令和输出空间。

续写超出本地预算，或收到可识别的模型上下文错误或 HTTP 413 时，会在同一部小说里分批总结前文并继续本次写作。每批将已有摘要和新读入的正文合并更新；超长单章会拆成几批读取。优先保留续写点所在章的原文，只有仍放不下时才总结这章。已经收到新章正文时不自动重跑。固定设定或写作要求仍放不下时，提示缩减。

顶栏「上下文」按整本小说估算书末续写的请求大小。手动压缩优先保留最新一章的原文；只有一章、或现有摘要已经覆盖到最新一章时，也会整理该章。可用滑杆调整 1–99% 的压缩率（默认 50%，即目标摘要为原文的一半，目标最多 4000 字符），也可填写压缩提示词（最多 2000 字符，用于指定优先保留的内容）。再次压缩会从原文重新整理，自动压缩使用默认参数。摘要只写入当前作品的 `checkpoint: { throughChapterId, summary }`，正文、阅读和导出保持原样。续写和总结以 `archivedChapters` 代替它覆盖的原文；摘要跨过续写点时不使用。停止或压缩失败不会保存半份摘要。

「摘要预览」展开后显示已保存的 Markdown 摘要和覆盖章数，手动和自动压缩生成的摘要都可查看。

顶栏「文件」→「Fork」以相同世界设定新建房间，把书名、写作设定、完整章节及已有摘要原样复制到新作品，不调用 Writer。写入本机失败时尝试清理刚建的空房间；成功后打开副本。副本有自己的房间 ID 和 Writer 会话。

**摘要失效**：被覆盖的任一章节被编辑、删除、拆分、合并或移动，或者摘要指向的章节已不存在，摘要就会被清除，之后恢复发送原文。

## 9. 导入、导出与背景总结

**导出小说**：直接读取页面中的章节，不等待保存完成，所以也是本机写入失败时保留成稿的方式。文件名中的非法路径字符替换为 `_`。

- TXT：第一行是书名；没有章号的标题补上“第 N 章”；正文中与章标题格式相同的行加反斜杠转义。
- Markdown：`# 书名`，每章 `## 标题`，正文原样输出。
- 不包含草稿、创作设定、角色资料和续写摘要。

**保存到服务器 / 从服务器同步**：仅开发模式。正文已对齐时，页面和文件菜单只显示「数据已同步」，两个方向都不可点。打开作品时如果正文不一致，页面和菜单才出现可点击的同步方向，由你点选，不会自动覆盖。

比较三处时间：本机 `updatedAt`（书名或章节变化时更新）、上次对齐时记下的 `syncedAt`，以及服务器 TXT 的修改时间。正文相同、还没有这些时间时，只补上时间，不提示。文风、大纲、每章字数、下一章要求和续写摘要仍只在当前浏览器。

「保存到服务器」把与「导出整本 TXT」相同的正文交给 `POST /api/novel/save-txt`，写入 `data/novels/<作品 id>/<书名>.txt`。该目录里上一份正文会写成唯一的 `<原文件名>.txt.bak`，更早的备份和多余 TXT 会删掉。另一部作品用自己的 id 目录，不会互相覆盖。正文没有变化时不替换这份备份。

「从服务器同步」用 `GET /api/novel/save-txt?id=<作品 id>` 读到的最新 TXT 覆盖本机书名和章节。本机上一份留在 IndexedDB 的 `previous`，同样只留一份；正文没有变化时不替换它。文件菜单的「恢复本地备份」把它换回来，换的时候现在的正文成为新的备份。不校验登录、房间或正文。生产环境不显示这些菜单，接口返回 404。服务器文件留在仓库里，也不代替本机下载。

**导入小说**：接受 ≤2 MB 的 `.txt` 或 `.md`，确认覆盖后才会写入。

- TXT：每章以单独一行的“第 N 章”开头（支持中文数字，可带分隔符和副标题）。第一章之前的单独一行如果与文件名一致、用书名号括起，或后面紧跟第一章，就作为书名。读取时还原转义的行。带章号的章节即使超过 8000 字也不拆分。
- Markdown：文件开头的 `#` 标题（不是章号格式时）作为书名；`##` 标题，或任意级别中形如“第 N 章 / 节 / 回 / 集”“Chapter N”的标题，作为章节分隔。
- Markdown 的章节，以及 TXT 第一章之前没有章号的正文，超过 8000 字时会按段落或行拆成多段，标题加“（续 N）”。
- 拒绝空文件、二进制内容和背景总结文件。
- 保存成功后整本替换：书名与章节换成导入内容，文风、大纲、字数和下一章要求重置为默认值，清除续写摘要、本章要求和草稿。世界设定不变。保存失败时原小说保持不变。从服务器同步时，标题和正文都没变的章节保留本章要求；内容有变化的章节按文件重建，不带 `brief`。

**总结并导出背景**：

- 需要至少一章。生成成功后下载 `书名-背景总结.md`，同时在页面显示总结，可以「再次导出总结」。任何保存都会清除这份预览。
- 文件结构：
  - 标题：`# 书名 · 背景总结（截至第 N 章）`
  - 正文：可阅读的 Markdown 总结
  - 末尾：`<!-- novel-background … -->` 注释，内含 `format: "novel-background"`、`schemaVersion: 1`、`source`（书名、章数、最后一章 ID）、`createdAt` 和完整世界配置（含角色私有资料）
- 这个文件可以导入到任意世界的「前置剧情」，导入时只取正文。

## 10. 已知限制

- 开发模式下，服务器 TXT 和本机正文用时间戳判断是否分叉。打开作品时只提示，不自动覆盖。没有服务器文件时，正文只在当前浏览器。删除房间不会清理本机记录、本地备份或服务器 TXT。复制世界、JSON 备份都不包含章节。
- 没有跨标签页写入协调。多个标签页同时编辑同一本小说时，最后写入的会覆盖之前的。
- 生成草稿的备份只在当前浏览器。续写 / 整章润色、选段润色和剧情整理的待应用结果都会按账号和作品备份；刷新后恢复，生成不会接着跑。保存失败后没有单独的“重试保存”，下一次成功写入会保存整本当前内容。
- 浏览器取消会传到服务端和代理，但上游是否立即停止计算或计费，由代理和模型决定。
- 输出上限为 8192 tokens，目标字数较大时仍可能被截断。截断时已生成的续写 / 润色正文留在可编辑草稿并标明未写完；摘要截断不会采用。
- 导出和背景总结不会做语义脱敏，模型写进正文的秘密会原样导出。
