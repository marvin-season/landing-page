# 开放世界：小说模式

## 1. 核心决策

一个 Writer 统一负责情节、人物言行、叙事视角、文风和章节衔接。角色是作者掌握的创作资料，不是轮流调用的 Agent。写章、润色和剧情整理由同一个 `world-writer` 执行，每次仅发送当前操作的指令和上下文；总结使用独立的档案指令。

| 项目 | 剧本 | 小说 |
| --- | --- | --- |
| 产物 | 按顺序发生的对白与旁白消息 | 按章排列的连续正文 |
| 生成职责 | 调度器选人，actor / narrator / summary 分工 | 一个 Writer |
| 人物私有资料 | 按角色隔离 | 作者全部可见，按剧情揭示 |
| 推进方式 | 自动接续多批 | 作者每次触发一个任务，不自动连写 |
| 正文存档 | 服务端房间 | 当前浏览器 IndexedDB |
| 生成接口 | `POST /api/group-chat/rooms/:id/runs` | `/api/novel` 创建、读取或停止任务 |

## 3. 设定来源

```ts
type Chapter = { id: string; title: string; text: string; brief?: string };

type Novel = {
  title: string;
  style: string;
  outline: string;
  chapterGoal: string; // 下一章要求
  words: string; // 每章目标字数（表单字符串）
  chapters: Chapter[]; // 数组顺序即章节顺序
  checkpoint?: { throughChapterId: string; summary: string }; // 续写摘要
  background?: ImportedNovelBackground; // 当前无写入入口
};
```

- **首次打开**：本机没有记录时，用 `createNovel(config)` 初始化：书名取世界名称，大纲取 `storyGoal`，文风为默认的第三人称，每章 4000 字。没有存档时显示本机提示。开发模式的服务器 TXT 只参与对账，确认同步后才覆盖正文。
- **修改设定**：在顶栏「设定」中修改。小说房间的编辑器把「故事推进要求」换成「创作设定」，包括小说名称（≤100）、文风与叙述视角、大纲与创作要求（≤12000）。保存时先写入本机小说，再把大纲截取前 4000 字写入 `config.storyGoal`，然后 `configure` 世界配置。配置保存失败时尝试恢复本机设定。详情顶栏和作品列表优先显示本机书名。大厅导入、仍为默认占位设定的小说首次进入时，顶栏下显示可关闭的弱提示，引导「去设定」或「从正文更新设定」；关闭后本机记住，同一作品不再显示。
- **在大厅创建小说时**：本机还没有小说记录，编辑器只显示「大纲与创作要求」，内容写入 `storyGoal`，首次打开时再据此初始化。
- **下一章要求与每章目标字数**：在阅读页底部填写，目标字数范围为 1000～8000，随每次输入保存到本机。
- **本章要求**：续写开始时，若「下一章要求」去掉空白后还有内容，就记下这段文字。应用该次草稿时写入新章的 `brief`。同一章草稿重新生成后，以最后一次实际送出的要求为准；要求留空则不保留 `brief`。润色、剧情整理、导入、手动保存和从服务器同步都不会新写 `brief`。它只留在本机小说里，不进入 Writer 上下文，也不写入导出的 TXT。草稿保存后，如果当前输入仍与该章实际使用的要求相同，就清空输入框。
- **生成时读取**：每次生成都读取当前 `room.config` 和本机小说。修改设定只影响之后的生成，不会改写已有章节。
- **写作模型**：使用第一个启用角色的模型，全部禁用时用第一个角色的模型。小说编辑器里角色的启用开关显示为「候选写作模型」，启用状态不影响角色资料是否交给 Writer。小说房间可以随时增减角色。

## 4. Writer 任务与上下文

请求体为 `{ roomId, prompt, task }`，外层 `task` 取 `chapter`、`rewrite` 或 `summary`。浏览器按本次操作选取上下文并组装成 `prompt` 内的 JSON 字段。写章和编辑共用固定的 Writer 通用指令；`task.instructions` 只写本次操作的范围、衔接要求和输出格式，作者输入单独放在 `task.requirements`。粘合输出 `{ ending, opening }` JSON，拆分输出 `{ secondOpening }` JSON，其他写章和编辑操作输出正文。

- **完整世界设定**：整个 `WorldConfig`。
- **世界基本设定**：`title`、`background`、`scene`、`rules`、`facts`、`storyGoal`、`characters`，不含 `priorContext`。

两者都包含全部角色的全部资料。剧本消息和剧本摘要都不会发给 Writer。

续写、整章润色和选段润色共用预设信息（完整世界设定、书名、文风和大纲）与章节上下文规则。摘要只覆盖前文时，用它代表已覆盖的正文，只补发尚未覆盖的前文章节；摘要超出本次操作范围时，改用范围内的前文原文。续写以前一章为界（即当前选中的章），润色以目标章之前为界，目标章正文单独提供。

| 功能 | task | 发送的上下文 |
| --- | --- | --- |
| 续写下一章 | `chapter` | 完整世界设定；书名、文风、大纲；无摘要时发送截至所选章的标题和正文，摘要未超过所选章才使用；正文只补入摘要未覆盖的前文。章间续写额外参考紧接着一章的开头（最多 1200 字符）；`task` 含新章章号、目标字数、8000 字上限和下一章要求（留空时为“承接前文与大纲，推进下一阶段情节。”）。 |
| 剧情插入 | `chapter`，`task.mode: "insert"` | **第一章之前**：发送完整世界设定（含前置剧情）、书名、文风、大纲、本次写作要求、字数限制、原第一章开头和已有导入背景。**章间**：发送完整世界设定、书名、文风、大纲、插入要求、字数限制及所选两章的完整正文（`previousChapters` / `followingChapters` 各一章）。章号和默认标题按插入后的位置编号。超过 150,000 字符则报错。 |
| 润色整章 | `rewrite` | 共用预设和章节上下文；目标章（章号、标题、正文）；润色要求（留空时为“改善语言、节奏和过渡，保留关键剧情。”）。开启「精简上下文」后，保留预设、目标章和要求，省略历史章节上下文。 |
| 润色选段 | `rewrite` | 共用预设和章节上下文；完整目标章正文拆成 `selection: { before, text, after }` 以标记替换范围；润色要求。替换长度上限为 8000 减去选区外文字的长度。开启「精简上下文」后，保留设定、要求和标记过选段的本章正文。 |
| 剧情粘合 | `rewrite`，`task.mode: "stitch"` | 完整世界设定；书名、文风、大纲；所选前一章的结尾和后一章的开头（各约 1,200 字符，边界对齐到段落或句末，短章取全文），以 JSON `{ ending, opening }` 放入 `targetChapter.text`；所选两章中紧邻改写区的保留原文（各 ≤600 字符）；过渡要求和两段各自的长度上限。要求模型输出 JSON。 |
| 剧情合并 | `rewrite`，`task.mode: "merge"` | 完整世界设定；书名、文风、大纲；所选连续章节的章名和完整正文，按章序以 JSON 数组放入 `targetChapter.text`；选中范围外前一章的结尾、后一章的开头（各 ≤600 字符）；固定的单章压缩要求（去重、抹除接缝，保留关键事件、伏笔和人物变化），以及选填的本次写作要求。超过 150,000 字符则报错。 |
| 总结并导出背景 | `summary` | 完整世界设定；书名；已完成章节的标题和正文（有效摘要会代替它覆盖的章节）。不发送文风、大纲和下一章要求。 |
| 拆分章节 | `rewrite`，`task.mode: "split"` | 完整世界设定；书名、文风、大纲；所选章的章号、标题、完整正文和选填的拆分要求。AI 摘录第二章开头的原文，客户端验证后拆成两章。也可以直接手动把光标放在第二章的开头，预览后应用，手动拆分不调用模型。 |
| 续写上下文压缩 | `summary` | 完整世界设定、书名、已有摘要或导入背景、本批待压缩的正文，以及按压缩率计算的累计摘要目标字符数和选填的压缩提示词。多批次依次更新同一份剧情摘要。 |

续写、普通润色和总结在没有有效摘要时发送已有的导入背景；精简润色省略导入背景。剧情整理不发送续写摘要，剧情插入有导入背景时会发送。导入背景以 `importedBackground` 字段传递。

悬停在续写、润色、剧情整理或上下文压缩按钮上，可查看操作作用和发送给 AI 的内容。润色提示随整章、选段和「精简上下文」切换；剧情插入提示随书首或章间切换。手动写章、保存及应用草稿等操作会提示不向 AI 发送内容。

**不调用模型的操作**：编辑与保存正文、查看修改、删除选区、切换章节、删章、导入导出小说、应用或丢弃草稿，以及复制小说（只创建房间并写入本机）。

## 5. Writer 接口

[`/api/novel`](../../src/lib/group-chat/novel.ts) 要求登录。创建和取消校验同源 `Origin`。任务按账号、作品和任务 ID 隔离。

- `POST` 校验 `roomId`、`runId`、世界配置 `version`、`task` 和不超过 150,000 字符的 `prompt`。作品必须属于当前账号、为小说且未结束。任务保存后返回 202。同一任务 ID 重试会接回原任务。
- Writer 独立于浏览器请求运行，仍使用当前世界的写作模型和原有会话标识。生成使用服务端选择的写作指令，工具禁用，`maxSteps: 1`、`maxOutputTokens: 8192`、`maxRetries: 0`。服务端消费 AI SDK 消息流，定期保存正文快照及完成状态。
- `GET ?roomId=…&runId=…` 读取同一任务的最新快照。`DELETE` 主动停止任务并保留已保存的输出。关闭页面只停止读取。

## 6. 任务生命周期

同一浏览器按账号和作品记录当前任务。运行时锁定会改写章节的操作。浏览器后退、离开作品、刷新、关页或断网后，在同一浏览器重新打开作品会读取原任务。仍在生成时继续显示进度，已完成时恢复本次操作的结果。续写、润色和剧情整理的结果仍需确认后写入正文。

长篇的上下文压缩可能分多个 Writer 请求。离开时正在运行的批次继续执行，重开后用保存的进度安排后续批次或续写。主动停止、输出截断和失败仍按对应任务处理。

| 任务 | 完成后 |
| --- | --- |
| 续写 | 输出到编辑草稿，点「应用草稿」才在续写起点之后插入新章，并带上这次送出的本章要求。原有后文保留，后续默认章号顺延。停止后已收到的正文仍可编辑，草稿需非空且不超过 8000 字才可保存。刷新后恢复的续写草稿仍记住这次要求 |
| 整章润色 | 和续写一样输出到编辑草稿。结束或停止后可修改草稿，点「应用草稿」才替换当前章 |
| 选段润色 | 将输出实时放回编辑草稿的原选段位置，两侧正文保留。结束或停止后可继续编辑，点「应用草稿」才写入正文 |
| 剧情整理 | 解析为 `PlotDraft`：粘合需能解析出 JSON 的两个字段，合并 / 插入需 ≤8000 字，解析失败报错，成功后可编辑合并稿、插入稿或两段粘合过渡，再确认应用 |
| 背景总结 | 生成背景文件、下载、在页面预览 |
| 上下文压缩 | 分批生成摘要。自动压缩随续写使用，手动压缩由作者确认应用；停止或失败不保存半份摘要 |

**应用草稿前的校验**：本机小说对象与发起时相同，世界配置 `version` 未变，房间未结束。恢复待应用的润色或剧情稿时验证原正文或保存版本，原正文已变的旧剧情稿可从文件菜单导出。

**保存**（`update`）：

- 默认先更新页面，再进入串行写入队列，写入 IndexedDB。保存失败时提示先导出，内容仍留在页面。
- 编辑器保存、剧情整理应用和导入使用 `persistFirst`，写入成功后才更新页面，失败时保留原内容。
- 每次保存都会检查续写摘要是否仍然有效，见[第 8 节](#8-续写上下文归档与-fork)，并清除本页的背景总结预览。

**结束 AI 创作**之后，接口拒绝所有 Writer 任务，页面也禁用续写、润色和剧情整理。手动编辑、导入和导出仍然可用。

## 7. 阅读、编辑与润色

### 阅读页

- 房间顶栏在空闲时显示已完成章数，保存中则加上「正在保存…」。阅读区不再单独放「小说创作」标题。房间顶栏的「文件」菜单包含导入小说、Fork、上下文、导出整本 TXT 和总结并导出背景。
- 房间顶栏的「提示词历史」按最新在前显示已提交的非空写作要求原文，不区分续写、润色或剧情整理。记录按账号和作品独立保存在当前浏览器，不进入 Writer 上下文，也不随小说导入、导出或复制。点「填入」把这段文字写入当前打开的输入框（阅读页的下一章要求、编辑页的润色指令，或已打开的剧情整理「本次写作要求」），不自动提交，也不切换到别的面板。
- 「文件 → 上下文」打开续写上下文弹窗：按整本估算书末续写请求大小，可手动压缩归档前文，或展开查看已保存的摘要。
- 章节用分页切换。本机按账号和作品记住当前阅读章节，刷新后仍停在该章；没有记录或该章已不存在时停在最后一章。吸顶栏是分页：上一章、章号、下一章。不超过 5 章时列出全部章号；超过 5 章后最多同时显示 5 个章号，保留第一章、最后一章和当前章两侧的相邻章号，跳过的章号收成省略号。章节末尾是「上一章」「下一章」。省略号不紧贴当前章：点到紧挨省略号的章号后，窗口会挪开，把当前章和相邻章展开。点击省略号打开下拉，格子里是被收起的章号，顶部显示指向的章名，点选后切到该章。当前章高亮，悬停章号可看章名。正在构思的新章排在最后，用虚线框标出。切章时，章首已在视口内则保持滚动位置，否则回到章首；短章也保留足够的阅读区高度，避免顶栏跳动。新章内容轻微上移并淡入，系统启用减少动态效果时直接显示。阅读页未聚焦输入框时，可用 ← / → 切换。正在构思、润色或导入时不可切换。吸顶操作栏把分页、本章字数和操作按钮排在同一行；窄屏时分页单独占一行。栏内显示当前章字数和每章目标字数（正文字符数，与编辑器相同；不记录当时目标的章节只显示本章字数；本章不足目标 75% 时标「偏短」），并有：
  - 「编辑本章」。本机草稿尚未保存为正文时，分页中的对应章号用红字显示，当前章字数旁显示红色提示：草稿未同步，点击「编辑本章」进入。
  - 「章节操作」菜单：剧情整理、删除本章。粘合和章间插入需选择相邻且都有正文的两章。合并可向两端扩选至少两章连续且有正文的章节，确认后以一章替换所选范围，后续默认章号随位置调整。合并正文最多 8,000 字，可能大幅缩短；预览显示原文总字数与草稿字数。「剧情插入」也可选择「第一章之前」，只需已有一章，无需该章有正文。「拆分章节」选择一章，默认选中当前章（有足够正文时）。切换方式或丢弃草稿重试时保留要求。合并和拆分可留空，粘合和插入必填。
    章节格只显示章号，悬停可看章名。草稿生成后收起设置区；丢弃草稿后回到原选择和写作要求。
- 正文可以从底部磨砂玻璃输入框后方滚过。点击「继续创作下一章」展开，小字会显示接在哪一章之后以及新章章号；空书从第 1 章起写，阅读区提供「填写下一章要求」一键展开并聚焦输入。填写要求、确认目标字数后点「AI 续写」；按钮带魔杖图标。同一行旁边是「手动写下一章」，直接打开空白新章，不调用模型。保存后才插入当前续写起点之后，不写入本章要求。故事已结束时仍可手动开写。正在构思、润色或导入时两个入口都不可用。收起时保留输入。等待正文时留在阅读页，分页停在新章并用虚线框标出；收到正文后再进入编辑器。书名为空或每章字数无效时不能续写。续写上下文超过上限时提示导出当前卷，到新世界继续。
- 阅读页章名可直接修改。点章名进入编辑，回车或离开输入框后保存，最多 80 字；留空则恢复当前位置的默认编号。只匹配「第N章」的标题在拆章、插入、合并或删章后按新位置重编号，自定义标题保持原样。正在构思、润色或导入时不能改章名。
- 当前章有本章要求时，标题下显示原文和「用作下一章要求」。点击后把这段文字写入底部「下一章要求」，展开输入框并聚焦，不开始生成。正在构思、润色、导入或故事已结束时不能填入。

### 拆章与删章

- **拆章**：在「剧情整理 → 拆分章节」中，可让 AI 选择拆分位置，也可手动指定。先预览两章，再确认应用。两章拼接后与原文完全相同。原章保留标题，新章插在后面并采用默认编号；后续默认标题会重新编号，自定义标题保持不变。
- **删章**：确认后删除并保留一个本地版本，可从文件菜单恢复。

### 编辑模式（`ChapterEditor`）

- **编辑草稿**：编辑页只显示居中的可编辑草稿，宽度与阅读页正文一致；已保存正文通过「查看修改」对照。顶栏显示「编辑草稿」或「查看修改」以及当前字数 / 8000 字上限。每章草稿按账号、作品和章节独立保存在当前浏览器的 IndexedDB。切换章节、返回阅读或刷新后，再进入该章会恢复草稿；没有草稿时以已保存正文开写。草稿不会上传、导出、随 Fork 复制或进入 AI 上下文。聚焦时高亮光标所在行。
- **底部润色**：编辑页底部有与阅读页相同的磨砂输入条，浮在草稿上方。草稿区保持全高；正文底部按输入条高度留白，滚到末尾时最后几行仍露在输入条上方。默认收起为「润色本章」。点击输入条，或划选正文后，输入条展开；展开后填写润色指令（选填）和「精简上下文」，点「开始润色」。划选后同一条输入改为「润色选段」，并可删除选区。续写新章时不显示这条输入，仍用章内的重新生成表单。
- **生成新章**：草稿区接收正文。生成中草稿只读，可以停止生成或向上滚动查看已生成的内容。点「返回阅读」可继续看已保存的章节。阅读页右上角的常驻通知提供「查看进度」，任务结束后可点「打开草稿」。通知可手动关闭，关闭后仍可从「文件」菜单打开进度或草稿。润色也使用这个入口。滚回末尾后恢复自动跟随。结束或停止后可编辑草稿，也可在草稿区底部修改要求后重新生成。新一轮还没有收到正文时保留上一稿。「应用草稿」首次保存成功后留在当前章的编辑页。
- **手动开写下一章**：从阅读页底部「手动写下一章」进入。正文从输入开始自动备份，点「保存章节」后才插入续写起点之后。空白新章返回时不占目录。不调用模型，也不写入本章要求。
- **保存**：「保存章节」写入成功后，草稿成为新的稳定版本，并清除该章的草稿记录；失败则保留草稿。超过上限时不能保存。
- **新章草稿**：手动写作和 AI 续写的新章在正式保存前按作品留在本机 IndexedDB，记录续写起点。返回阅读或刷新后，目录选中该草稿，显示红字「请先保存草稿」，可重新编辑或丢弃。每部作品一次保留一份新章草稿；保存或丢弃后才能再写下一章。如果原续写位置已经不存在，可确认将新章保存到书末。草稿不参与正文、AI 上下文或导出。
- **生成草稿备份**：整章和选段润色写入该章的编辑草稿。打开作品时可接回正在生成的润色或剧情整理任务，也可恢复已完成的待应用结果。
- **查看修改**：双栏对比稳定版本和当前草稿，对齐相邻的相似行，只给实际增删的文字和换行上色。整行新增或删除时标出整行。大范围重写超出细比上限时，会保留首尾一致的文字，将其余区域标为替换。可以直接在对比页保存或应用草稿。
- **切换章节**：草稿存到本机后可直接切换，无需保存为正文。正在写入或生成时不能切换；未入目录的新章仍需先保存或返回阅读。
- **离开保护**：已有章节的草稿存到本机后可以直接返回阅读；未入正文的新章会先完成本机写入，再返回阅读。草稿写入尚未完成或失败，或新章尚未保存为正文时，离开作品会提示确认。生成中可以离开，重开作品后接回任务。

### 润色

编辑页和剧情整理弹窗都可打开提示词历史，填入当前输入。既有章节草稿可以主动放弃。原正文已经改变时，恢复的草稿会提示核对差异。

- **共同流程**：有未保存草稿时，先保存章节。点击「开始润色」后显示「思考中」，保留原文；收到首批文字就开始替换草稿，集中到达的文字分小步显示。可以停止生成。结束或停止后，输入条隐藏，仍可编辑草稿、查看修改或应用草稿。「应用草稿」成功后留在编辑页。
- **选段润色**：划选正文后，选段高亮，底部输入条展开并改为「润色选段」。发送已保存的目标章并标记选段。模型只输出选段的替换文字，草稿只在原位置替换并保留高亮，前后未选正文保持原样。「删除选区」可以直接编辑草稿。
- **整章润色**：未划选时，展开底部「润色本章」。发送完整的已保存章节作为改写目标，模型输出整章替换稿，逐步替换整个草稿正文。应用后返回阅读时高亮整章结果。
- **默认上下文超限**：提示开启「精简上下文」；精简后仍超限，可先压缩前文或缩短本章正文及设定。
- **离开保护**：润色生成中可以返回阅读或离开作品。手动编辑的草稿尚未写入本机时，离开会提示确认。

## 8. 续写上下文归档与 Fork

整本正文存在本机 IndexedDB，没有 150,000 字符的整本上限，实际可用量取决于浏览器存储。续写检查序列化后的 `prompt` 长度（最多 150,000 个 UTF-16 码元）以及完整请求体编码后的大小（前端预算 384 KiB）。模型自己的窗口按 token 计算，另计固定指令和输出空间。

**归档**：把已完成前文压缩成剧情摘要，写入本机 `checkpoint: { throughChapterId, summary }`。正文、阅读和导出保持原样；发给 Writer 时以 `archivedChapters: { throughChapter, summary }` 代替它覆盖的章节原文，只补发尚未覆盖的前文章节。从摘要范围内的旧章续写时，仅发送到续写点的前文原文，必要时单独压缩本次前文。故事结束后不能再压缩。

续写超出本地预算，或收到可识别的模型上下文错误或 HTTP 413 时，会在同一部小说里分批归档前文并继续本次写作。每批将已有摘要和新读入的正文合并更新；超长单章会拆成几批读取。优先保留续写点所在章的原文，只有仍放不下时才归档这章。已经收到新章正文时不自动重跑。固定设定或写作要求仍放不下时，提示缩减。自动归档使用默认压缩参数。

从顶栏「文件 → 上下文」打开「续写上下文」弹窗，查看按整本小说估算的书末续写请求大小，以及当前摘要覆盖了前几章。手动压缩优先保留最新一章的原文；只有一章、或现有摘要已经覆盖到最新一章时，也会整理该章。可用滑杆调整 30%～70% 的压缩率（默认 50%，即目标摘要为原文的一半，目标最多 4000 字符），也可填写压缩提示词（最多 2000 字符，用于指定优先保留的内容）。再次压缩会从原文重新整理。手动压缩先预览，点「应用摘要」才替换。停止或失败会保留上一份已应用摘要。

「摘要预览」展开后显示已保存的 Markdown 摘要和覆盖章数，手动和自动压缩生成的摘要都可查看。

顶栏「文件」→「复制整本小说」以相同世界设定新建房间，把书名、写作设定、完整章节及已有 `checkpoint` 原样复制到新作品，不调用 Writer。写入本机失败时尝试清理刚建的空房间；成功后打开副本。副本有自己的房间 ID 和 Writer 会话。

**摘要失效**：被覆盖的任一章节被编辑、删除、拆分、合并或移动，或者摘要指向的章节已不存在，`checkpoint` 就会被清除，之后恢复发送原文。

## 9. 导入、导出与背景总结

**导出小说**：以 TXT 下载正文。直接读取页面中的章节，不等待保存完成，所以也是本机写入失败时保留成稿的方式。文件名中的非法路径字符替换为 `_`。

- TXT：第一行是书名；没有章号的标题补上“第 N 章”；正文中与章标题格式相同的行加反斜杠转义。
- 不包含草稿、创作设定、角色资料和续写摘要。

**保存到服务器 / 从服务器同步**：仅开发模式。正文已对齐时，右上角显示可手动关闭的「数据已同步」常驻通知，文件菜单收起两个同步方向。打开作品时如果正文不一致，页面和菜单才出现可点击的同步方向，由你点选，不会自动覆盖。

比较三处时间：本机 `updatedAt`（书名或章节变化时更新）、上次对齐时记下的 `syncedAt`，以及服务器 TXT 的修改时间。正文相同、还没有这些时间时，只补上时间，不提示。文风、大纲、每章字数、下一章要求和续写摘要仍只在当前浏览器。

「保存到服务器」把与「导出整本 TXT」相同的正文交给 `POST /api/novel/save-txt`，写入 `data/novels/<作品 id>/<书名>.txt`。该目录里上一份正文会写成唯一的 `<原文件名>.txt.bak`，更早的备份和多余 TXT 会删掉。另一部作品用自己的 id 目录，不会互相覆盖。正文没有变化时不替换这份备份。

「从服务器同步」用 `GET /api/novel/save-txt?id=<作品 id>` 读到的最新 TXT 覆盖本机书名和章节。本机上一份留在 IndexedDB 的 `previous`，同样只留一份；正文没有变化时不替换它。文件菜单的「恢复本地备份」把它换回来，换的时候现在的正文成为新的备份。不校验登录、房间或正文。生产环境不提供服务器同步，接口返回 404。本机的删章、剧情整理、整本导入和手动摘要应用也会留下上一份备份，文件菜单可恢复。服务器文件留在仓库里，也不代替本机下载。

**导入小说**：接受 ≤16 MB 的 `.txt` 或 `.md`，确认覆盖后才会写入。

- TXT：每章以单独一行的“第 N 章”开头（支持中文数字，可带分隔符和副标题）。第一章之前的单独一行如果与文件名一致、用书名号括起，或后面紧跟第一章，就作为书名。读取时还原转义的行。带章号的章节即使超过 8000 字也不拆分。
- Markdown：文件开头的 `#` 标题（不是章号格式时）作为书名；`##` 标题，或任意级别中形如“第 N 章 / 节 / 回 / 集”“Chapter N”的标题，作为章节分隔。
- Markdown 的章节，以及 TXT 第一章之前没有章号的正文，超过 8000 字时会按段落或行拆成多段，标题加“（续 N）”。
- 拒绝空文件、二进制内容和带旧版标记的背景总结文件。
- 保存成功后整本替换：书名与章节换成导入内容，文风、大纲、字数和下一章要求重置为默认值，清除续写摘要和本章要求。已有章节草稿可以从文件菜单单独导出。世界设定不变。保存失败时原小说保持不变。从服务器同步时，章名和正文能明确匹配的章节保留原 ID 和本章要求，即使位置变了也能找到对应草稿。

**总结并导出背景**：

- 需要至少一章。生成成功后下载 `书名-背景总结.txt`，同时在页面显示总结，可以「再次导出总结」。任何保存都会清除这份预览。
- 长篇超出单次上下文时分批总结，最终文件只包含纯文本总结。可以在下一卷的「前置剧情」中导入。旧版 Markdown 背景总结仍可导入。

## 10. 已知限制

- 开发模式下，服务器 TXT 和本机正文用时间戳判断是否分叉。打开作品时只提示，不自动覆盖。没有服务器文件时，正文只在当前浏览器。删除房间不会清理本机记录、本地备份或服务器 TXT。复制世界不包含章节。
- 同一浏览器的小说正文写入会验证本机保存版本。发现另一页已经保存时，提示刷新核对，保留当前页面中的草稿。
- 可在同一浏览器内恢复生成任务和草稿。服务端生成结果可查询 24 小时，正文仍在本机。每个 Writer 请求最多运行 280 秒，服务端重启或运行超时后可恢复已保存的部分。
- 主动点「停止」会取消服务端任务。上游是否立即停止计算或计费，由代理和模型决定。
- 输出上限为 8192 tokens，目标字数较大时仍可能被截断。截断时已生成的续写 / 润色正文留在可编辑草稿并标明未写完；摘要截断不会采用。
- 导出内容为正文或总结文本。模型写进正文或总结的秘密也会一同导出。
