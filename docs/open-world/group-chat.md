# 开放世界：剧本模式

剧本由 2～7 位 NPC 用对白接续，旁白可选。操作者在故事之外，可以干预剧情，也可以代替某个角色或旁白写一条。房间、消息和摘要保存在服务端。页面、接口与数据归属见[运行架构](./architecture.md)。

## 1. 使用流程

1. 启动本地 Agent 代理，运行 `nr dev`，打开 `http://localhost:3001/agent/worlds/works`。
2. 在作品页「创建作品」，或到预设模板页「使用模板」/「使用」预设，选择「剧本」，填写世界与规则、故事推进要求、旁白开关和 NPC。也可以在作品页「导入小说」：正文独立收录到「我的作品」并用默认设定打开；之后在作品「设定」里可自行填写，或「从正文更新设定」。「对话节奏」区可以获取代理模型列表，或测试连接（会调用一次第一个角色的模型）。
3. 创建后进入详情页，房间处于 `draft` 状态，页面自动发起第一批。
4. 运行中可随时「暂停」。暂停后可以「继续故事」，或用「仅下一条」只生成一条。
5. 运行中「设定」按钮不可用，需先暂停。故事开始后不能增减角色，但可以修改资料、启用状态和模型；要增减角色请复制为新世界。
6. 「设定」面板提供导出对话 Markdown、导出旁白 Markdown、复制世界和结束故事。结束后只能查看和导出 Markdown。

## 2. 输入身份

对话可以从底部磨砂玻璃输入框后方滚过。点击单行输入框，展开身份选择、发送和故事推进操作。默认身份是「系统」，支持 `@` 点名已启用的角色。收起输入框会保留未发送的内容。

| 身份 | 存为 | 含义 |
| --- | --- | --- |
| 系统 | `intervention`，`speakerId: "user"` | 系统干预。可以只 `@` 角色不写文字，这时存为“让指定 NPC 优先行动，随后继续自动推进。” |
| 旁白 | `narrator`，`speakerId: "system"` | 这条就是旁白正文，不再另外生成旁白 |
| 已启用角色 | `agent`，该角色的 `speakerId` | 这条就是该角色已经说出的对白 |

操作者写的消息带 `operator: true`，作为已发生的剧情直接存入房间，不调用 Agent 改写。

- **运行中提交**：中止当前一批（正在生成的回复标为 `interrupted`），写入这一条，再立即开始新的一批。
- **暂停时提交**：只保存这一条，不运行。点「干预并继续」（系统身份）或「发送并继续」（旁白、角色身份）则保存后立即运行。带 `@` 点名的提交总会立即运行。
- **点名**：被 `@` 的角色依次占用本批的前几条发言，本批条数取 `max(点名数, maxTurns)`。

## 3. 运行与批次

一次 `POST rooms/:id/runs` 对应一个 `WorldRun`，`mode` 有四种：

| mode | 条数 | 结束状态 | 用途 |
| --- | --- | --- | --- |
| `auto` | `max(点名数, maxTurns)` | `completed` | 自动推进、继续故事、提交输入 |
| `step` | 1 | `paused` | 仅下一条 |
| `retry` | 1，指定原发言者 | `paused` | 重试最新一条失败、中断或截断的回复 |
| `save` | 0 | 暂停 | 只保存输入（接口支持，页面未使用） |

**自动接续**：[`worldStoryStream`](../../src/lib/group-chat/client.ts) 在一批 `auto` 正常完成（未暂停、`run.status === "completed"`、发言数达到上限）后，带 `continueRunId` 自动发起下一批。服务端只在该运行仍是当前已完成的 `auto` 运行时接受续跑。单步、重试、暂停、出错和离开页面都会停止接续。

**重试**：只对最新一条非系统消息生效。这条消息必须是角色对白或旁白，状态为 `failed` / `interrupted` / `truncated`，生成时的配置版本与当前一致，且发言角色仍处于启用状态。

**暂停**：页面取消订阅，再调用 `POST rooms/:id/stop` 并带上 `runId` 与 `clientRequestId`。服务端把运行标为 `paused`，同时把这个请求 ID 记为 `cancelled`。如果开跑请求比暂停请求晚到，会被拒绝，故事不会被重新启动。

**幂等与冲突**：每个请求带 `clientRequestId` 和 `expectedVersion`。同一 ID、同一内容重复提交时直接返回当前房间；同一 ID 内容不同时返回冲突；配置版本不一致时要求刷新。

**页面同步**：空闲时每 4 秒轮询一次房间，窗口重新获得焦点时也会刷新。运行中以 SSE 事件更新消息。未完成的回复超过两条时，只显示最近两条，其余折叠；折叠条提示可展开查看已生成片段。未完成气泡按截断 / 中断 / 失败标明状态，正文保持可读，并在最新一条提供「重试这一条」。

## 4. 选人规则

[`nextTurn`](../../src/lib/group-chat/schedule.ts) 是纯规则函数，不调用模型。下面用到的判断只看公开历史，即状态为 `complete`、类型不是 `system` 的消息。

先计算几个信号：

- **点名**：`run.mentions[turn]`，本批第几条对应第几个点名。
- **干预提示**：最新一条是系统干预，且没有直接称呼某个角色。以 `?` 或 `？` 结尾的算问句。
- **对话停滞**：最近连续对白中，最后三条去掉人名和标点后内容相似；或连续对白达到 4 条，而最近 4 条只有两人以内在说话。
- **直接称呼**：最新一条不是旁白，并以 `名字，`、`@名字`、`…，名字？` 等形式直接称呼另一位已启用角色。连续对白达到 4 条后，这个信号失效。
- **叙事间隔**：连续对白达到 3 条。

发言者依次取：被点名的角色 → 被直接称呼的角色 → 最近发言最少的已启用角色（统计最近 `角色数 × 2` 条对白，平局时取较早发言者）。

旁白开启时，以下情况改为旁白叙述：非问句的系统干预、对话停滞、到达叙事间隔，以及开场（还没有任何完成的对白或旁白）。点名、问句干预和直接称呼优先交给角色，其中直接称呼最多让旁白推迟到连续 4 条对白。旁白关闭时，这些情况都由上面选出的角色发言。

每轮给 Agent 的 `direction`：

| 情况 | direction |
| --- | --- |
| 角色普通或点名发言 | 轮到你发言，结合当前情境与自身目标自然接话，把互动往前推进一步。 |
| 角色回应直接称呼 | 刚有角色直接同你说话或向你发问，请当场回应对方并推进对话。 |
| 角色回应干预 | 在故事内以角色身份自然回应最新系统干预，不跳出戏外对操作者说话。 |
| 旁白开场 | 依据初始场景、前置剧情与已知事实写一段开场旁白，建立当下情境。 |
| 旁白回应非问句干预 | 依据最新系统干预叙述当前场景与可见变化。 |
| 旁白打破对话停滞 | 当前对话出现重复或停滞，请落实角色已表露的行动结果或引入合理的场景变化，打破僵局。 |
| 其余旁白 | 承接刚才的角色言行，写出可见的动作结果或场景变化，推进一小步。 |

## 5. 角色上下文

[`context.ts`](../../src/lib/group-chat/context.ts) 为每次调用组装消息。信息隔离由程序保证：

- **公开角色资料**只包含 `id`、`name`、`identity`、`personality`、`publicInfo`、`style`，不含 `goal` 和 `privateInfo`。
- **actor** 收到公开世界设定、所有角色的公开资料，以及自己的完整资料（含目标和私有资料）。
- **narrator** 只收到公开世界设定和公开角色资料。
- 房主可以查看全部设定。“秘密”指角色之间的模型输入隔离，不是对房主保密。

actor 和 narrator 的消息顺序：

1. **system**：角色职责（只说自己的话，不写动作、心理或替他人说话；旁白不代写对白、不泄露秘密）、故事连续性约定和消息布局说明。
2. **user**：固定资料 `{ world, yourCharacter }`（旁白只有 `world`）。`world` 包含 `background`、`priorContext`、`initialScene`、`rules`、`initialFacts`、`storyGoal`、公开角色资料。
3. **按时间排列的未摘要公开历史**：自己说过的话作为 `assistant` 原文，其他发言和干预作为 `user`，内容为 `{"publicEvent": {seq, speakerId, name, kind, text, mentions}}`。
4. **user**：`{ world: { latestIntervention, summary }, direction }`。

固定资料放在前面，变化的摘要和任务放在最后，这样前缀稳定，有利于代理侧缓存。整组消息序列化后超过 26,000 字符时，本轮报错并暂停，提示缩减设定。

**摘要**：未摘要的公开历史超过 30 条，或序列化后达到 10,000 字符时，每轮开始前先调用 summary。压缩范围不含最近 6 条，单次最多约 13,000 字符，循环执行直到不再超限。summary 的输入是 system 指令、`{ confirmedFacts }`、`{ previousSummary, messages }`，输出不超过 5,000 字符，写入 `room.summary`。原始消息全部保留。修改配置后摘要会清空并重新整理。

## 6. 引擎执行

进程启动时，[`route.ts`](../../src/app/api/group-chat/[[...path]]/route.ts) 调用一次 `createWorldHandlers`，内部用 `createWorldEngine(worldStore, completeText)` 得到 `execute`，之后每一批都调用它。

1. `store.begin` 在一个事务里完成：校验类型（小说返回 409）、幂等、版本、续跑条件、点名和重试目标；中止旧运行；写入操作者消息；创建新的 `WorldRun`（租约 15 秒，时限 180 秒）。
2. `execute` 等待被替换的旧运行完全退出后开始，每 5 秒续一次租约。每一轮依次：按需摘要 → `nextTurn` 选人 → 追加一条 `streaming` 消息 → 调用 actor 或 narrator → 期间流式推送 `delta`，并每 500 毫秒保存一次已生成的片段 → 成功后标为 `complete`，`turns + 1`。
3. 本批正常结束时，`auto` 运行标为 `completed`，`step` / `retry` 标为 `paused`。
4. 出错或被中止时，当前消息按原因标为 `truncated`、`interrupted` 或 `failed`，运行标为 `interrupted` 或 `failed`，房间暂停。

**事件**：`room`、`phase`、`message`、`delta`、`error`、`done`，每个事件带 `runId` 和递增的 `eventSeq`。

**模型选择**：actor 使用被选中角色的模型；narrator 使用 `GROUP_CHAT_DIRECTOR_MODEL`，未设置时使用本轮选出的角色的模型；summary 使用第一个启用角色的模型。

**调用限制**（[`provider.ts`](../../src/lib/group-chat/provider.ts)）：

- 每批最多 25 次调用、180 秒。
- 单次调用总时长 60 秒，30 秒没有新数据即超时。
- 对白和旁白最多 2,000 字符，达到上限按截断处理，不进入后续剧情。
- 要求 `finishReason === "stop"` 且正文非空，否则视为不完整。
- 用量由代理上报时累计 token，费用未知。

## 7. 配置变更与存档

- 修改配置要求房间没有正在进行的运行，且版本一致。成功后 `version + 1`、追加快照、清空摘要。房间已开始时会自动暂停，并插入一条 `system` 消息「房主更新了世界设定，后续对话使用新的设定」。`system` 消息不进入剧情上下文。
- 每次存档操作都在事务里读取、修改并写回整个房间 JSON，同一进程内串行执行。
- 读取房间时，如果运行的租约或时限已过，会把运行标为 `interrupted`，不会自动续跑。
- 服务骤停时，最后一次保存之后生成的片段会丢失。
- 导出对话 Markdown 会标注未完成的消息；导出旁白 Markdown 只包含旁白。

## 8. 服务端配置

均只在服务端读取，示例见根目录 `.env.example`：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `GROUP_CHAT_BASE_URL` | `http://127.0.0.1:3425/v1` | OpenAI 兼容代理地址，剧本和小说共用 |
| `GROUP_CHAT_API_KEY` | `magpie` | 代理密钥 |
| `GROUP_CHAT_DIRECTOR_MODEL` | 未设置 | 旁白模型 |
| `GROUP_CHAT_DATABASE_URL` | `file:./db/group-chat.db` | libSQL 地址 |
| `GROUP_CHAT_DATABASE_TOKEN` | 未设置 | 远程 libSQL 令牌 |

## 9. 运行边界

- 运行状态（中止控制器）保存在单个常驻 Node 进程里。远程部署时 `127.0.0.1` 指向服务器自身，必须配置服务器能访问的代理和持久化数据库。
- 每个房间只有一位操作者。没有多人协作、私聊、历史分支、媒体生成和工具执行。
- 关闭页面或断开连接会取消当前一批。应用侧取消不代表上游一定停止计算或计费。
- 上下文预算按字符估算，并非各模型的精确 token 窗口。
- 世界规则只是叙事约束，由模型落实，程序不保证具体的故事结果。暂停、预算、权限和私有资料过滤由程序保证。
